<analysis>**original_problem_statement:**
The user requested a full-stack application in German to manage orders at a festival with multiple food/drink stands.

**PRODUCT REQUIREMENTS:**
1.  **Roles:**
    *   **Rolle 1 (Bestellung/Ordering):** Takes orders and handles payments.
    *   **Rolle 2 (Küche/Kitchen):** Prepares orders and marks them as ready.
    *   **Rolle 3 (Ausgabe/Pickup):** Hands over completed orders to guests.
    *   **Rolle 4 (OneManShow):** A single person who handles all steps (ordering, payment, handover) for small stands. This role should process orders directly without a kitchen/preparation status.
2.  **Stands:**
    *   The system should support multiple stands.
    *   Stands can be categorized as Speisestand (food), Getränkestand (drinks), or gemischter Stand (mixed).
    *   The ordering interface should only show articles relevant to the selected stand type.
3.  **Admin Dashboard (auth: admin/admin):**
    *   Full CRUD for stands (add, delete, rename).
    *   Assign specific articles to specific stands.
    *   A setting per stand to allow skipping the kitchen preparation step.
    *   CRUD for articles.
    *   A system for managing deposit groups (Pfandgruppen) and assigning them to articles.
    *   View statistics, including an hourly breakdown of order count and revenue.
4.  **Ordering & Workflow:**
    *   A deposit system (Pfand) must be integrated. The ordering interface needs a way to add items with deposits and process deposit returns (Pfand zurück).
    *   In the order cart, items should be removable via a swipe-to-delete action.
    *   The kitchen view should display a live summary of all open items across all incoming orders.
    *   Orders should be sorted chronologically (First-In, First-Out).
5.  **UI/UX:**
    *   The UI must be responsive for mobile devices.
    *   The initial user flow should be: 1. Select Role (tile view) -> 2. Select Stand (tile view). The previous dropdown for stands should be removed.
6.  **Technology:**
    *   Updates between roles (e.g., a new order appearing in the kitchen) must be in real-time. This was implemented using WebSockets.

**User's preferred language**: German
